## Компактне порівняння

Покриття цільових інтервалів і спільне покриття — **100% для кожного методу** в таблицях. Колонка «Потік» включає весь 7-денний контекст і тому показує warm-up. Затримки — медіани лише виявлених подій, у хвилинах часу датасету; пропущені мають null, не 0. «Парні сигнали» — початки епізодів у незмінених потоках: у цільових вікнах / у всіх контекстах і хвостах. Повторювані часові ділянки сумуються як окремі сценарії, а не незалежні фізичні будинки.

### Що означають результати

- **Flatline:** обидві 30-хвилинні події не виявлено; усі чотири 60/120-хвилинні виявлено. IF/AE/residual/Unanimous не дали початку сигналу всередині цих шести подій. Затримки flatline —30,30,40,40хв: до ін’єкції вже були1–2 показання того самого значення, тож шість послідовних значень накопичилися раніше ніж через50хв від підміни. Це врахування реальної передісторії, не зміна duration.
- **Sustained high:** усі вісім 60/120-хвилинних втручань знайдено, всі чотири 30-хвилинні залишилися без сигналу цього правила. Для цих восьми нових сигналів затримка50хв — шосте послідовне показання. Параметри й погодинний профіль v2 незмінні.
- **Residual:** формально6/12 за зафіксованим onset-matching, але лише3 виявлення мали новий paired threshold crossing. В інших трьох незмінений потік також мав flag=true у момент сигналу; їх не можна приписувати втручанню. Основні6 не переписано, paired діагностику наведено окремо.
- **AE/IF:**3/12 і1/12 відповідно; Unanimous0/12. Це результати лише цього manifest і цих артефактів, а не універсальна перевага одного підходу.

## Контрольні ситуації та обмеження

- Одиничний+300Wh пік: у його одному цільовому інтервалі жоден із шести показаних методів не мав flag=true; sustained_high не видав його за тривале перевищення.
- Модельований нормальний ранковий профіль50→200Wh: sustained_high не спрацював. Flatline дав8 flagged points і1 новий епізод після встановлення денного плато. Це приклад **нормального повторення**, а не доведеної несправності. Такий профіль явно задано і для попередніх днів контексту; його не видаємо за натуральну нормальність UCI.
- Задане нормальне нульове споживання12 інтервалів: flatline дав7 flagged points і1 епізод; інші методи в цьому вікні —0. Правило коректно описує повторення, але **не розрізняє** нормальний нуль і підтверджене зависання. Автоматичне повідомлення «лічильник зламався» було б необґрунтованим.
- Сигнали на незмінених UCI-парах не названо підтвердженими false positives: справжньої fault-розмітки немає. Тому тут немає вигаданої operational precision/F1.
- Усі 3/6/12 інтервалів, обидва початки й обидві сили підвищення збережено, включно з невдалими випадками. [Розподіл за тривалістю/силою](by-duration-and-strength.csv) є агрегацією всіх передбачених сценаріїв, не додатковим пошуком параметрів.
- На графіках відмічені лише true flags; відсутній маркер може означати false або unavailable, відмінність збережена в nullable per-point файлах. Помаранчеве тло включає енергетичну тривалість останнього інтервалу; matching усе одно обмежено останнім **label**, без after-event grace.

## Відтворення без сервісів і навчання

Потрібні вже наявні датасет/артефакти з plan hashes та точний локальний image. Не виконувати automatic prepare, build, replay або migrations. З кореня repo, з **новою порожньою** output-directory:

```sh
mkdir -p /tmp/energy-rules-reproduction
docker run --rm --pull never --network none --read-only \
  --cap-drop ALL --security-opt no-new-privileges --memory 2g --cpus 1 --user 0:0 \
  --tmpfs /tmp:size=128m \
  -e PYTHONDONTWRITEBYTECODE=1 -e OMP_NUM_THREADS=1 \
  -e OPENBLAS_NUM_THREADS=1 -e MKL_NUM_THREADS=1 -e MPLCONFIGDIR=/tmp/matplotlib \
  -v "$PWD:/work:ro" -v /tmp/energy-rules-reproduction:/output:rw -w /work \
  sha256:3be9a8ff7a2eedf156ae4b85e4b2bd064b1fda84aa0057bf4718ab2f9ed4a865 \
  python -m diagnostics.rule_comparison --output /output/run2
```

Runner відмовляється перезаписувати directory і зупиняється при відсутніх/несумісних артефактах, зміненому manifest чи checksum. Новий run не має замінювати збережений `run1`.
