## Висновок

`sustained_high` додав **7 позитивних точок** до residual, збільшивши охоплення цього конкретного втручання з1/12 до8/12 (**8,33%→66,67%, +58,33 відсоткового пункту**). Усі7 додані точки — лише правило; одночасних позитивних residual+high під час втручання **немає**. Неперервного сигналу на всіх12 точках немає: hybrid має окремий сигнал13:20 і другий епізод14:10—15:20, з негативними рішеннями13:30—14:00 між ними.

AE має найбільше позитивних точок втручання —9/12; residual і hybrid реагують найраніше —на першій точці. High не створює додаткових позитивних точок після повернення ряду; IF має найдовший додатковий хвіст:15:20 і15:30. Unanimous не виявив це втручання. Ці критерії не встановлюють загалом найкращий алгоритм.

## Межі та закриття епізодів

Нижче — епізоди копії, що перетинають втручання. Початок і кінець — **позитивні точки**, а колонка закриття — наступний запис, на якому рішення вже не true. У контролі таких епізодів немає.

Окремі епізоди `sustained_high` у БД **не зберігаються**: для нього збережено assessments; наведені послідовності обчислені з їхніх flags. ML/Unanimous/hybrid — справжні DB episodes; усі їхні межі/кількості/статуси/причини перевірено проти перерахованих послідовностей у повному потоці. Для збережених закритих епізодів `updated_at` перевірено між `received_at` закривального й наступного вимірювання. Точне поле `closed_updated_at_utc` збережено вJSON/CSV; це час записування UPDATE, **не виміряний commit acknowledgement**. Час закриття за міткою вимірювання відновлено з наступного фактичного рішення й чинного коду закриття (`Repository.update_episode`, `persist_combined`, `rules.persist`).
