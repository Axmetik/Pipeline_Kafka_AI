# Інтерпретація Stage 4

Повні результати: [згенерований звіт](results/report.md). Цей текст написано
після завершення зафіксованого експерименту. Пороги, параметри й сценарії не змінено.

## Рекомендація

За погодженим правилом validation обрано **Forecast Residual Detector**:
середній event F1 на змішаних validation-сценаріях — 0.02353, проти 0 для IF/AE.
Усі три пройшли обмеження частоти фонових тривог ≤1% на clean validation.
Проте такий рівень F1 є низьким. Residual — відносний переможець цього
експерименту, **жоден із трьох детекторів не рекомендується як готова система
операційного виявлення несправностей**.

На п'яти змішаних test-сценаріях (основний поріг99%) residual виявив одну з
29 ін'єктованих подій, IF/AE — жодної. Macro event recall residual — 5%,
micro event recall — 1/29≈3.45%: це різні способи усереднення, не суперечність.
Вибір не змінюємо за test. Затримка єдиного виявлення — 0 хв за дискретністю
даних10хв; решта28 подій пропущені. Ця нульова затримка не означає хорошу
загальну якість; для IF/AE затримка не визначена через відсутність виявлень.

## Калібрування і наслідки для історії

Train IQR — 50Wh; для прикладу, зафіксовані spike амплітуди дорівнюють
100/200/300Wh, а основний residual-поріг — 296.246Wh абсолютної помилки.
Додавання300Wh до поточного навантаження не обов'язково створює residual>296Wh.
Пороги з 99-го перцентиля відображають значну природну мінливість цього ряду.
Це можливе пояснення низької чутливості; це не доказ причинності.
Невеликі контекстні зміни можуть залишатися в межах звичайних значень ознак,
а тривале втручання стає частиною лагів і прогнозів.

Альтернативні заздалегідь визначені пороги98% і99.5% оцінено без зміни основного
режиму. На mixed test поріг98% не поліпшив recall, але збільшив background
спрацювання;99.5% не виявив жодної ін'єкції. Не підбирали інший поріг за test.

На mixed test середня кількість спрацювань після завершення подій у вікні144
інтервали — IF6.8, AE5.0, residual8.6. Вони включають як можливі наслідки
зміненої історії, так і звичайні фонові спрацювання: без причинного порівняння
не приписуємо всі tail alarms самій ін'єкції. Вони не зараховані в event TP.
Післяподієві спрацювання залишено у synthetic background errors.

## Незмінений контроль і межі висновків

На незмінених3946 test-точках IF дав28 тривог, AE23, residual32 — відповідно
0.710%,0.583%,0.811%. Це **не підтверджені false positives**, оскільки UCI
не має достовірної аномальної розмітки. Незмінені високі навантаження не були
позначені аномаліями за самим значенням енергії.

Цільова частка втручань —2%, але правила тривалості/відстані не завжди дозволяли
заповнити весь бюджет. На test фактична частка по всіх сценаріях — приблизно
0.91–1.98%; фактичні значення кожного запуску збережено. Stuck має однакову силу
в усіх трьох severity-повторах; це не три різні амплітуди. Synthetic labels
означають контрольовану підміну, а не доведену фізичну несправність.

Test уже переглядався у Stage2/3. Параметри RF також історично обиралися з
використанням Stage3 validation, хоча RF Stage4 заново навчено лише на train.
Цей експеримент не є незалежною перевіркою на невідомому будинку.

Наступне дослідження має окремо зафіксувати підхід до контекстного калібрування
та перевірку на нових часових даних або реальних мітках. Коригування цього test
для кращої таблиці не виконувалося. Чинні HGB forecasting та IoT не замінено.
